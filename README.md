# مدونتي — مدونة شخصية (React + Tailwind CSS v4 + Supabase)

مدونة شخصية كاملة: صفحة رئيسية بشبكة مقالات وبحث وتصفية حسب الوسوم، صفحة
قراءة تدعم Markdown مع صور وفيديوهات يوتيوب مضمّنة في أي مكان من النص،
تعليقات قرّاء مع مراجعة قبل النشر، ولوحة تحكم محمية بتسجيل دخول لإضافة/
تعديل/حذف المقالات وإدارة التعليقات.

## البنية التقنية

- **React 19** + **Vite** — واجهة المستخدم
- **Tailwind CSS v4** (عبر `@tailwindcss/vite`، بدون ملف إعداد منفصل)
- **React Router v7** — التنقل، بما فيه مسارات متداخلة داخل `/admin`
- **Supabase** — قاعدة البيانات (`posts`, `comments`)، التخزين
  (`blog-images`)، والمصادقة (Auth)
- **marked** + **dompurify** — تحويل Markdown إلى HTML وتعقيمه
- تصميم **RTL** بالكامل مع خطوط عربية (Reem Kufi للشعار، El Messiri
  للعناوين وواجهة الاستخدام، Noto Naskh Arabic لنص المقال الكامل)

## 1) إعداد مشروع Supabase

1. أنشئ مشروعاً جديداً على [supabase.com](https://supabase.com) (مجاني) —
   أو استخدم مشروعك الحالي إذا كنت بنيت النسخة السابقة من هذه المدونة.
2. من القائمة الجانبية، افتح **SQL Editor** → **New query**، الصق محتوى
   الملف `supabase/schema.sql` بالكامل، ثم اضغط **Run**. الملف **آمن
   لإعادة التشغيل** حتى لو نفّذت نسخة سابقة منه — كل الجداول والسياسات
   تُنشأ أو تُحدَّث بدون أخطاء. هذا الملف ينشئ/يحدّث:
   - جدول `posts`: `id`, `title`, `content`, `image_url`, `video_url`,
     `tags` (مصفوفة نصوص)، `created_at`.
   - جدول `comments`: `id`, `post_id`, `author_name`, `content`,
     `is_approved`, `created_at`.
   - سياسات RLS: القراءة عامة (والتعليقات المعتمدة فقط تظهر للزوار)،
     أما الإضافة/التعديل/الحذف فمقتصرة على المستخدم المسجّل دخوله —
     التفاصيل في القسم 3 أدناه. التعليقات الجديدة تُنشأ دائماً غير
     معتمدة (`is_approved = false`) بغضّ النظر عمّا يُرسله المتصفح.
   - مخزن (bucket) باسم `blog-images` بوصول عام للقراءة، والرفع/الحذف
     فيه مقتصران على المستخدم المسجّل دخوله.
3. من **Project Settings → Data API**، انسخ **Project URL**.
   من **Project Settings → API Keys**، انسخ مفتاح **anon public**.

## 2) إعداد متغيرات البيئة

```bash
cp .env.example .env
```

ثم افتح `.env` وضع القيم التي نسختها:

```
VITE_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
```

## 3) حماية لوحة التحكم (تسجيل الدخول)

مسار `/admin` محمي بتسجيل دخول عبر Supabase Auth، ولا يوجد نموذج تسجيل
عام (Sign Up) — عمداً، حتى لا يقدر أي زائر إنشاء حساب لنفسه. الحساب
الوحيد المسموح به هو حسابك أنت، ويُنشأ يدوياً من لوحة Supabase:

1. من لوحة Supabase: **Authentication → Users → Add user**.
2. أدخل بريدك الإلكتروني وكلمة مرور، وفعّل خيار **Auto Confirm User** حتى
   يصبح الحساب جاهزاً للدخول فوراً بدون تأكيد بريد.
3. من **Authentication → Sign In / Providers**، عطّل **Allow new users to
   sign up**. هذه الخطوة **ضرورية أمنياً**: بدونها، أي شخص يقدر يستدعي
   `auth.signUp()` مباشرة عبر واجهة Supabase ويصبح "authenticated" بنفسه.

بعد هذا: رابط "لوحة التحكم" لا يظهر في القائمة العلوية إلا لمن سجّل
دخوله، وأي زائر آخر يفتح `/admin` مباشرة سيرى نموذج تسجيل دخول فقط —
الحماية الفعلية في سياسات RLS على قاعدة البيانات، وليس فقط في إخفاء
الرابط بالواجهة.

## 4) لوحة التحكم: ما الجديد

بعد تسجيل الدخول على `/admin`، ثلاث تبويبات:

- **مقال جديد**: نفس نموذج النشر السابق، مع حقلين إضافيين:
  - **الوسوم**: اكتب وسوماً مفصولة بفواصل (مثال: `سفر، يوميات`) — تظهر
    كأزرار قابلة للنقر في الصفحة الرئيسية لتصفية المقالات حسب الوسم.
  - **نص المقال يدعم Markdown الآن**: `**عريض**`، `*مائل*`،
    `## عنوان فرعي`، واقتباسات بـ `>`. لتضمين **صورة في أي مكان** من
    النص: `![وصف](رابط الصورة)`. لتضمين **فيديو يوتيوب في أي مكان**:
    الصق رابط الفيديو وحده في سطر منفرد — يتحوّل تلقائياً إلى مشغل فيديو
    متجاوب في مكانه بالضبط. حقل "رابط فيديو رئيسي" القديم ما زال يعمل
    كما هو (يظهر أسفل المقال)، فتقدر تستخدم الاثنين معاً أو أحدهما فقط.
- **إدارة المقالات**: قائمة بكل المقالات، مع زرّي **تعديل** و**حذف**
  لكل واحد. الحذف نهائي ويحذف أيضاً صورة الغلاف من Storage تلقائياً.
- **التعليقات**: كل تعليق يرسله زائر يبقى **"بانتظار الموافقة"** ولا
  يظهر للعامة حتى تضغط **قبول** من هذا التبويب — حماية بسيطة من
  الرسائل المزعجة (Spam). يمكنك حذف أي تعليق في أي وقت.

## 5) التشغيل بـ Vite

يتطلب [Node.js](https://nodejs.org) إصدار 18 أو أحدث.

```bash
npm install       # تثبيت الحزم (فيها حزمتان جديدتان: marked و dompurify)
npm run dev       # تشغيل خادم التطوير (عادة على http://localhost:5173)
```

للبناء والمعاينة كنسخة إنتاج:

```bash
npm run build      # يُنشئ مجلد dist/ جاهزاً للنشر
npm run preview    # معاينة نسخة الإنتاج محلياً
```

## نشر الموقع (اختياري)

عند النشر على Vercel/Netlify أو أي استضافة ثابتة:
- أضف نفس متغيرات البيئة (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`)
  في إعدادات المشروع على منصة الاستضافة.
- بما أن التنقل بين الصفحات يتم عبر React Router (من جهة العميل)، **يجب**
  تفعيل "SPA fallback" وإلا ستحصل على `404 NOT_FOUND` عند فتح رابط مباشر
  مثل `/post/123` من جهاز آخر أو عند تحديث الصفحة:
  - **Vercel**: ملف `vercel.json` في جذر المشروع (مرفق في المشروع) بمحتوى:
    ```json
    { "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }] }
    ```
  - **Netlify**: ملف `public/_redirects` بمحتوى `/* /index.html 200`.

## ملاحظة حول التعليقات العامة

نموذج التعليقات مفتوح لأي زائر بدون تسجيل دخول (تجربة استخدام أسهل لشخص
يريد فقط أن يعلّق)، لكن كل تعليق يمرّ بمراجعتك أولاً قبل أن يظهر للعامة.
لا يوجد حالياً حدّ لعدد التعليقات التي يمكن لشخص واحد إرسالها في وقت
قصير (rate limiting) — إذا واجهت إزعاجاً كبيراً لاحقاً، أخبرني وأضيف طبقة
حماية إضافية.
